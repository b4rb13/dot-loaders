<section id="ownership">

## Render content and guards in the right owner [#ownership]

The DOM-free native `/server` entry exports `renderStatic(description)` and exact CSS arrays. It emits escaped library decoration. It does not accept your application HTML, serialize provider callbacks, render your data or protect pending application content for you. Escape untrusted application data in your own template.

The React adapter supplies static placeholder markup and initial owner state. The frozen adapter does not by itself conceal application children before native definition: the runnable apps include a `:not(:defined)[state=pending]` visibility rule in application CSS. That rule preserves layout and ends when the native owner takes over. Native templates own their content's initial `hidden`, `inert`, busy and accessible presentation themselves. Unknown raw custom tags reserve no useful skeleton pixels unless you provide the static path and the correct CSS. Use the ordinary document recovery link outside any pending/inert subtree.

The React example includes a runnable `native-static.ts`: `bun native-static.ts` prints a ready application-owned fragment, and `bun native-static.ts pending` prints its guarded pending form. Its `renderStatic` call draws only the placeholder. It is a template example, not a complete native enhancement app; the [native catalog examples](/docs/components) provide explicit registration and live controls.

</section>

<section id="initial-tree">

## Match the first client render [#initial-tree]

Use the same state, cycle, content and CSS policy on the server and first client render. A request nonce is scoped to that document, never a module-level constant. Avoid clocks, random initial content, browser-only measurements or a client-only mask that disagrees with the server. Keep providers and target refs in the client boundary; establish them before requesting their corresponding handoff.

Hydration attaches event handling to the existing React tree. Do not replace the content container, invent a second readiness state or blanket-suppress mismatches. A useful regression check captures the real input before the bootstrap runs, hydrates, and verifies the same node and value afterward. Update configuration during a load and verify that the owner/cycle stays unchanged.

The [React SSR example](#example-react-ssr) uses `renderToReadableStream` on Bun. [React's server reference](https://react.dev/reference/react-dom/server/renderToReadableStream) describes that Web Streams API; Node applications can use the corresponding Node renderer instead. This is not a universal server-adapter abstraction in the package.

</section>

<section id="fallback">

## Plan for missing JavaScript or CSS [#fallback]

A static placeholder is decoration, not a progress report. Keep semantic content and application status outside decorative hosts. Reserve the real content's space with application classes and matching typography. CSS assets and inline authorization must exist before enhancement. If scripts fail, the server HTML and ordinary recovery link must still make sense; if a page starts pending, the link should produce an available server-rendered outcome.

In these examples, all loading actions start disabled and become available after the client handlers attach. The ready page is readable without JavaScript. The pending page keeps content guarded by application CSS and exposes recovery. That CSS must load; CSP/stylesheet failure is a separate fallback case, not a confidentiality boundary. Never send sensitive data merely because a visual loading guard hides it. This scoped implementation does not resolve the older Quickstart control-admission gap or the WebKit retry problem tracked in #34.

Do not assume that blocked styles are equivalent to a successful enhancement. Test cold stylesheet failure separately from a document that has already admitted the same cached stylesheet. Test reduced motion, visitor pause and failed/delayed JavaScript without clearing or fabricating readiness.

</section>
