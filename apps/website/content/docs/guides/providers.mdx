<section id="capture">

## Read geometry synchronously at setup [#capture]

A chart or table `targetProvider` supplies final geometry for its own placeholder surface. It runs during handoff setup, not on every idle frame or as a data-fetching subscription. Return a finite, bounded supported input or `null`. Keep network requests, readiness, event handling and target ownership in application code.

The example waits for its required stylesheet responses and document fonts before enabling loading controls. Its table provider reads only its known table and marked text spans using [Range geometry](https://developer.mozilla.org/en-US/docs/Web/API/Range/getBoundingClientRect), then returns plain numeric/string data. It does not mutate application DOM, change state/cycle, return a promise, start timers or retain engine commands. Private counters illustrate the number of setup calls; they do not drive readiness.

The engine captures its own immutable copy. An application's original provider object is not the engine's later live model. Configuration changed during a captured handoff applies under the frozen lifecycle rules; target or geometry invalidation can discard that plan safely.

</section>

<section id="cases">

## Compare supported and fallback cases [#cases]

The Provider case selector exposes seven declared scenarios:

- `valid` returns finite chart geometry and measured semantic table cells.
- `retry` returns `null` once per provider, then supplies its data. Only `null` permits one immediate retry; this is not polling.
- `unavailable` returns `null` twice. The content still becomes available through the simple fallback.
- `invalid` deliberately injects NaN into geometry. This is a fault demonstration; do not copy it into production providers.
- `throw` deliberately throws once. Exceptions are diagnostics and fallback, not a reason to keep data loading forever.
- `missing-row` omits one registered table row target while keeping its cell projection, demonstrating incomplete semantic ownership.
- `international` preserves unsupported table text and returns `null` instead of inventing ASCII glyphs. The chart provider remains independent.

Open Provider calls and owner events to inspect the current call counts and bounded history. Under moving, unrestricted automatic handoff, valid providers are called once; null retry uses at most two calls. Explicit region animation skips child provider sampling. Motion restrictions settle playback immediately but can still perform bounded setup reads, so providers must stay cheap even when motion is paused. Do not equate a zero count with a failed request or force motion just to obtain a provider sample.

</section>

<section id="coordinates">

## Match the actual coordinate system [#coordinates]

DOM rectangles are viewport-relative, as described in [Element.getBoundingClientRect](https://developer.mozilla.org/en-US/docs/Web/API/Element/getBoundingClientRect). The sample subtracts the current placeholder origin to produce local CSS-pixel cells and glyphs; chart data scales into the supplied content-box bounds. It does not multiply by device pixel ratio. These conversions assume the plain, untransformed layout shown in the application. A rotated/scaled widget or padded plot needs its own correct transformation.

Refresh geometry calls the public `refresh()` methods after application-owned layout or typography changes. Recycled DOM requires a new explicit target list, not just a redraw. The engine's resize/visibility machinery remains authoritative; a user provider is not an alternative scheduler or renderer.

The table function handles plain printable-ASCII text nodes only. A compound DOM cell, a loading font, zero-size surface or unsupported text returns `null`. It is deliberately not a universal text shaper, virtualized-grid adapter or library-specific integration. Keep the original content readable when those assumptions fail.

</section>

<section id="cleanup">

## Discard stale plans without discarding the content [#cleanup]

Use the row-recycle action during handoff to invalidate captured row ownership; use a new report load to supersede the previous cycle. The actual content and note input stay under the same owner, and the old effects must not survive on the current rows. Nested detail state stays independent. A terminal presentation event is separate from the application's request outcome.

The sample attaches one application event listener per declared event name and removes those listeners at its integration lifetime. Observations are bounded and update outside the owned content after actions/events. It adds no animation-frame loop, private engine access, renderer selector or global readiness registry.

</section>
