## Choose the client boundary [#boundary]

Import `LoadingRegion` from `@dotquilt-internal/react/region` and the placeholder from its selective React entry. The adapter registers its own native definitions. Do not wrap the native tag in another readiness controller or call registrars while rendering.

In a framework that supports Server Components, the interactive composition belongs in a `'use client'` module. Pass serializable initial data and server-rendered children across that boundary; construct provider callbacks, custom animation definitions and DOM refs in the client module. A client boundary can still produce server HTML—it does not mean client-only rendering.

This guide targets the exact private `0.0.0-m2.0` artifacts. [Quickstart](/docs#setup) lists their identities. These packages are not published to npm.

</section>

<section id="state">

## Own the request and preserve the content [#state]

The complete example starts ready. Its buttons model outcomes; they do not fetch data. Start a new `cycle` with each application request. Use `pending` for replacement, `refreshing` to retain interactive current content, and `ready` when the current result can be presented. Keep the real content mounted under the same owner. An input or counter should survive refresh, reveal and ordinary configuration changes.

A real request needs cancellation and stale-result protection in your application. Only the current request may set the outcome. The library's handoff events describe presentation, not network success; an animation ending must never complete your request. On failure or cancellation choose the appropriate content/error presentation and announce it in your application. A handoff-only immediate outcome can use `timing={{duration:0}}`; clear that override before a later animated cycle.

`motion="paused"` is authoritative. Keep a visible pause control, honor system preferences, and let the engine bound its animation window. Ref/geometry refresh is explicit. A React rerender is not a new load and an equivalent option object is not a reason to reset a cycle.

</section>

<section id="hydrate">

## Hydrate the same initial tree [#hydrate]

For an existing server-rendered React tree, use `hydrateRoot` with the same initial content, state, cycle and style policy. Use `createRoot` for a genuinely client-created tree. Do not render new markup over server output or suppress hydration warnings to hide a mismatch. [React's hydration reference](https://react.dev/reference/react-dom/client/hydrateRoot) explains this boundary.

The example uses React's server renderer in a Bun response, then hydrates that same document. Controls are disabled until their client handlers are ready. Pending output retains an ordinary recovery link outside the hidden/inert content. No-JavaScript users can open the available server content.

</section>

<section id="complete-example">

## Run the complete React example [#complete-example]

Save all files below and add the reviewed tarballs to `vendor/`. Run `bun install --ignore-scripts`, `bun run build`, `bun run check`, then `bun run start`. Open `http://127.0.0.1:4233/?mode=external`. Add `&state=pending` to inspect pending server HTML. `mode=nonce` and `mode=hash` exercise the other styling policies.
