<section id="ownership">

## Choose the owner before the animation [#ownership]

The example's outer LoadingRegion owns one illustrative report. Its placeholder combines a heading skeleton, ChartLoader and TableLoader; TypingDots supplies the refresh indicator. The chart and table are decorations. They do not finish requests, emit independent readiness outcomes or fetch data. The actual report content stays mounted under the region.

The nested TextLoader owns its own detail state and cycle. Load detail while the outer report is ready, or keep it pending through an outer report cycle. The outer owner must not finish the detail's request or sample it as another outer placeholder. Ancestor visibility and pause still restrict its decoration. This is independent ownership, not a global all-or-nothing loading store.

</section>

<section id="coordination">

## Let family handoffs share the outer timeline [#coordination]

With no explicit region animation, owned rich sources prepare together and play on one shared timeline. Each source retains its own geometry and recipe. The total uses the maximum complete child recommendation rather than adding every child's duration. An explicit owner timing override replaces that shared total. The outer region emits one start and one terminal outcome for its choreography, not one request outcome per source.

The shared wrapper effect applies to all actual content in that region. It does not discover separate chart-content roots. If two areas need independent content reveal windows, give them independently controlled regions. Owned row effects still require explicit unique row targets, outside nested owners. A missing table target can fall back locally; conflicting writes or invalidated captured ownership must settle safely.

The report's observations disclosure records bounded provider-call and owner-event history outside the loading content. It is application instrumentation, not a public runtime diagnostics API. A provider does not update that DOM during capture or on every frame.

</section>

<section id="override">

## An explicit region handoff is authoritative [#override]

Turn on Use explicit region handoff to replace automatic child morphs with the included public `defineAnimation` region definition. It draws only a whole-content opacity reveal, on the engine's clock. The callbacks do not receive DOM or canvas objects, start timers, retain commands or infer readiness.

This path skips child provider sampling and rich convergence. It does not merge chart/table semantic inputs into a region snapshot. The complete file makes the precedence visible: the region receives its handoff binding, while children keep their idle bindings. Turn the option off to return to automatic family coordination on the next cycle. Changing configuration alone does not start a request.

</section>

<section id="lifecycle">

## Keep content, targets and focus stable [#lifecycle]

Refresh report leaves current content available; replacement loading guards its presentation. Keep the same input, actual rows and owner while changing ordinary settings. The Pause motion control applies to both owners; system motion and forced-color restrictions remain authoritative. A focus-sensitive replacement must preserve the runtime's established safe behavior rather than hiding the currently focused application control.

Recycle table rows intentionally replaces the actual row nodes and updates the target list. Try it during a moving handoff: the captured plan must be discarded instead of writing stale row effects. Starting a new report load also supersedes the previous presentation. Keep each request's cycle identity in the application; an animation end does not mean a network operation succeeded.

This sample models outcomes with buttons. A product still needs its own request cancellation, stale-result checks, errors, localization and persistent visitor preferences. The existing homepage/playground keep their own visitor-pause policy unchanged.

</section>

<section id="complete-example">

## Compare native and React ownership [#complete-example]

The two entry points implement the same report, independent detail, projection providers and first-party bindings. Native configures properties before explicit registration; React passes typed props and native refs through its thin adapter. Both use matching external CSS, useful static content and a disabled control state until required styles/enhancement are available.
