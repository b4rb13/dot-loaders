# Dotquilt website

Developers use this site to understand, try and adopt composable skeleton replacements. Dotquilt has a framework-independent Web Component core and a thin React adapter. Native and React examples receive equal treatment; the application owns data fetching and readiness.

The owner approved Guide documentation, a Workbench playground and Gallery examples in decision #11. This implementation follows that working prototype's reading/task structure without importing its simulated runtime. First useful flow: Quickstart → real loading composition → working code.

Current state: private development preview, exact packages 0.0.0-m2.0. No public npm release, final public namespace or deployment is claimed. M2/M4 qualification remains open, renderers provisional and publishing disabled. The API, animations and accessibility contracts are frozen for M5. Root/app tooling may change; the runtime may not.

Build: Bun/Turborepo, Next App Router, React and Tailwind. Success means readable server-rendered instructions, real package behavior, complete honest examples and accessible controls. Full nine-component content, search, share/version behavior and release qualification follow the six gates and 33 scenarios in #11.

## Owner-pinned homepage direction

The owner requests an elegant dark homepage in black, white and gray, retaining Dotquilt's dot theme and a striking animated experience. This replaces the first colorful homepage concept set; it does not automatically restyle the existing Guide/Workbench. The main action is Try the playground, with Docs secondary. Homepage motion should make dots resolve into real useful content, with restrained surrounding chrome, visitor pause/system authority and a useful static state. The owner selected The Dot Gallery composition on 2026-10-21: centered product promise and actions, a large dot-built “ready.” specimen, visible reveal controls, then chart/table specimens on a continuous lower band.
