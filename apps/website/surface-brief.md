# Guide and Workbench foundation

## Scope and mode
Guide is Read; Workbench is Operate. Implement the first loading-region/skeleton example, not a replacement marketing direction.

## Audience and job
Developers evaluating the package need to understand readiness, trigger real loading/reveal and obtain equivalent native/React code.

## Action and proof
Start loading, reveal content, pause motion, change line count and switch example integration. A real native runtime demonstrates the mechanism; synthetic copy is labelled. Code/setup remains readable without enhancement.

## Constraints
Private 0.0.0-m2.0 preview; frozen runtime; no public install/deployment claims. Useful content first, static on opening, visitor pause/system preferences authoritative. No prototype runtime imports. No invented metrics or testimonials.

## Direction and first viewport
Seed: approved-guide-workbench-2026-10-16. Warm paper, charcoal type, sage active states, thin rules, quiet system typography. Guide: compact navigation, readable article, supporting contents. Workbench: larger preview, nearby controls, code below. At 320px use a single column and collapsible navigation/code, never page-wide horizontal scrolling. The Guide first viewport explains the composition and private setup; Workbench shows the actual content/loading composition and explicit controls.

## Memorable interaction and open work
The package's own idle-to-content handoff is the authored motion; website chrome stays still. Full catalog/Gallery, local search, version history, exhaustive export/share/fallback coverage remain later M5 slices.

## Quality bar for this first slice

Useful reading before JavaScript; real loading/reveal without content remount on configuration edits; equivalent, complete native/React files verified against private tarballs; explicit version/setup and evidence limits. Desktop and 390/320px layouts reflow without page overflow; keyboard access and global pause remain visible. Quiet chrome leaves the package animation as the only authored moving moment. No claim of complete catalog, search, public distribution, browser-floor/manual-AT or performance qualification.

## Owner-authorized dark appearance — 2026-10-22

The owner extends Dot Gallery's black/white/gray appearance to docs and playground. Use near-black ground, readable near-white type, gray secondary text, a white primary action with black text, graphite code/specimen surfaces and explicit high-contrast control boundaries. Dark is the default static appearance, independent of JavaScript or OS light preference. Layout, system typography, dot/reveal motion and existing controls stay the same; this slice adds no theme toggle or persistence feature. Scope the palette to Guide/Workbench so the custom homepage remains unchanged. Forced colors retain system authority. This supersedes the warm-paper color direction only; readable articles, quiet chrome and existing Read/Operate behavior remain.
