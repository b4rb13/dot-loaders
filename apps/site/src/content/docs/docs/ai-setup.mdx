## What it does

<Steps>

1. **Learns Dotquilt** from these docs, as Markdown ([llms-full.txt](/llms-full.txt)), rather than from memory.

2. **Reads your project:** the framework and how it renders, how data loads, your styles and dark mode, any Content Security Policy, and every place that waits for content (spinners, hand-made skeletons, "Loading…" text, Suspense fallbacks). It leaves button spinners and upload progress alone.

3. **Shows you what it found and asks** only what the code can't tell it: which places to convert first, whether to replace an existing skeleton library, marks and colours, timing for fast responses. It waits for your answers before changing any file.

4. **Adds Dotquilt in order:** install, one-time setup (theme, CSP), then the most-seen place end to end, then the rest one at a time. Each placeholder gets the content's shape and size, and your data loading stays as it is: it only reads whether the data is pending, refreshing or ready.

5. **Checks its work:** types, lint, tests and build, then each place in the browser, in light and dark, on a narrow window and with reduced motion. It ends with a report of what changed and how to undo it.

</Steps>

## Use it

- **Paste it** into a new chat in your assistant's agent mode, at the root of your project. Review the plan it proposes before you answer its questions.
- **Or point to it.** If your assistant can read web pages, one line is enough:

  ```text
  Read https://dotquilt.dev/setup-prompt.md and follow it to add Dotquilt to this project.
  ```

It works with any framework: React 19, Vue 3, Svelte 5 and Angular 22 get their packages' components, and everything else (plain HTML, or an older framework version) gets the native elements.

## Docs for agents and tools

Agents and tools can read these docs without a browser. Every address below is a plain GET, with no key and no sign-in:

- **[llms.txt](/llms.txt)** is an index for language models: when to use Dotquilt, how to add it, and a link to every page as Markdown.
- **[llms-full.txt](/llms-full.txt)** holds every docs page in one file.
- **Every page as Markdown:** add `.md` to its address (`/docs/theming/` → `/docs/theming.md`), or ask for the page with `Accept: text/markdown`.
- **[setup-prompt.md](/setup-prompt.md)** is the prompt on this page.
- **[custom-elements.json](/custom-elements.json)** is the elements' [Custom Elements Manifest](https://github.com/webcomponents/custom-elements-manifest): every attribute, property, event, slot, CSS part and custom property. The [API reference](/docs/api/) is the same, for people.
- **[openapi.json](/openapi.json)** describes all of these as an OpenAPI 3.1 document, and the [API catalog](/.well-known/api-catalog) (RFC 9727) links to it.

### Errors

A request that doesn't ask for HTML (an agent or script sending `Accept: application/json`, `*/*` or no Accept header) for a page, or a `.md`, `.txt` or `.json` file, that doesn't exist gets a `404` with an RFC 9457 `application/problem+json` body: a `code`, what went wrong (`detail`) and what to do instead (`resolution`). If it prefers `text/markdown`, the 404 comes as Markdown. A browser gets the site's 404 page.

| `code` | Status | Meaning |
| --- | --- | --- |
| `page_not_found` | 404 | No page has that address. [llms.txt](/llms.txt) lists every page. |
